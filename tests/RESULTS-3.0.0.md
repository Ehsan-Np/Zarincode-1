# نتیجه آزمون زرین کد ۳٫۰٫۰

تاریخ اجرا: ۲۲ اکتبر ۲۰۲۶. محیط: نصب دورریختنی WordPress 7.1، Elementor 4.3.5، PHP 8.4، WooCommerce 11.2.1، Redux، SQLite و Chromium/Playwright. این نتایج به کد ۳٫۰ مربوط‌اند، نه انتقال اعداد آزمون نسخه قبل.

## PHP و یکپارچگی

| آزمون اجراشده | نتیجه |
|---|---|
| `native-design.php` | **۱۷۹۵ assertion موفق** روی ۲۳ مدل طرح اصلی: ثبت فیلد، اثر واقعی تغییر متن/متن غنی/پیوند/تصویر/آیکون، متن و آیکون Repeater، افزودن/حذف/ترتیب، هویت یکتای `_id`، مهاجرت ویرایش قدیمی، خروجی Query و رد مسیر مدل نامعتبر |
| `wordpress-integration.php` | **۲۳۲ بررسی موفق**: ۱۴ ویجت، کنترل‌ها و خروجی حالت سفارشی، HTML امن نمونه، پیوند، CPT و درون‌ریزی مجدد بدون افزایش محتوای دمو |
| `restore-and-identity.php` | **۲۷۲ بررسی موفق**: هویت رکوردها، CSS و نگه‌داری fixture طرح قبلی؛ آزمون اصلی موتور جدید در سطر اول است |
| `professional-inline.php` | **۹۷ بررسی موفق**: شش ویجت حرفه‌ای، تنظیمات/خروجی، کلیدهای inline و سازگارساز قدیمی؛ داده قدیمی صریحاً به fixture داده شده است، نه اینکه UI جدید از DOM متن استخراج کند |
| `professional-kit.php` | واردکردن واقعی کیت، رندر شش ویجت و تولید CSS موفق؛ قالب آزمایشی پس از آزمون حذف شد |
| `legacy-upgrade.php` | افزونه قدیمی واقعاً موقتاً جایگزین افزونه نصب‌شده شد؛ کلاس قدیمیِ فاقد `register_cpts_and_taxonomies`، جداسازی callbackها و درون‌ریزی در همان درخواست موفق؛ سپس افزونه جاری بازگردانده شد |
| اجرای بدون DOM | با حذف DOM و افزونه‌های وابسته از پیکربندی PHP، رندر هر ۱۴ ویجت اصلی موفق؛ `DOM=no` تأیید شد |
| همسانی هسته | `diff -qr` میان `zarincode-core/includes` و `zarincode/inc/EmbeddedCore`: بدون اختلاف |
| نحو | lint همه ۵۹ فایل PHP منبع/ابزار/آزمون و بررسی نحو JavaScript مرتبط موفق |

جمع چهار مجموعه عدددار: **۲۳۹۶ بررسی موفق**؛ نتایج مرورگر و کیت جداگانه‌اند.

## مرورگر واقعی و انتشار

`native-browser.cjs` روی برگه ساخته‌شده توسط `native-fixture.php` اجرا شد:

- رنگ `rgb(18,52,86)` و اندازه ۳۹px از قانون استایل بومی روی متن واقعی عنوان اعمال شد.
- همان قانون در عرض ۳۹۰px، اندازه responsive برابر ۲۴px داشت؛ عرض صفحه و عرض اسکرول هر دو ۳۹۰px بودند.
- فیلتر محصولات در یک نمونه، نمونه دوم همان ویجت را تغییر نداد؛ دو کارت مرتبط باقی ماندند.
- تب تعرفه، یک پنل مربوط را نمایش داد.
- ویرایش مستقیم عنوان با کلید `n_hero_hero_title_text_1`، مدل بومی Elementor را تغییر داد.
- ویرایش مستقیم عنوان کارت با کلید `n_services_services_grid_items_1.0.service_title_text_1`، رکورد Repeater را تغییر داد.
- انتشار واقعی از API ذخیره Elementor و بازخوانی صفحه عمومی: هر دو متن ویرایش‌شده باقی ماندند.
- خطای JavaScript ثبت‌شده در این سناریو: **صفر**.

`professional-browser.cjs` نیز جداگانه اجرا شد: ویرایش/انتشار متن اصلی و عنوان کارت حرفه‌ای، بقای عنوان تزئینی، نبود attribute ویرایشگر در HTML عمومی، حضور شش ویجت، مقایسه تصویر با ورودی/صفحه‌کلید/درگ ماوس، نبود overflow موبایل و نبود استثنای مرورگر: موفق.

## حفظ طرح اولیه

`native-visual.cjs` خروجی مرجع قدیمی و موتور جدید را با CSS و فونت‌های محلی در یک مرورگر و عرض ۱۴۴۰px مقایسه کرد. در **هر ۲۳ مدل**، متن نرمال‌شده برابر و اختلاف ارتفاع بیرونی حداکثر ۱px بود. این آزمون **pixel-diff تصویر نیست** و به معنی یکسان‌بودن تک‌تک پیکسل‌ها یا شکل دقیق آیکون‌های دو نسخه کتابخانه نیست. ظاهر و ساختار مورد پسند با رندر تنظیمات بازسازی شده، نه با تغییر طراحی به کارت عمومی.

## اجرای مجدد

فقط روی WordPress آزمایشی؛ برخی آزمون‌ها دمو می‌سازند یا محتوای برگه آزمون را منتشر می‌کنند:

```bash
php wp-cli.phar eval-file tests/native-design.php --path=/path/to/test-wordpress
php wp-cli.phar eval-file tests/native-fixture.php --path=/path/to/test-wordpress
# ID خروجی fixture و اطلاعات مدیر آزمایشی را به ZC_TEST_* بدهید.
# Playwright باید از مسیر اجرای اسکریپت قابل بارگذاری باشد.
node tests/native-browser.cjs
node tests/native-visual.cjs
```

متغیرهای مرورگر: `ZC_TEST_BASE_URL`، `ZC_TEST_PAGE_ID`، `ZC_TEST_ADMIN_USER` و `ZC_TEST_ADMIN_PASSWORD`. در آزمون بصری مسیر JSON مقایسه با `ZC_TEST_COMPARE_JSON` قابل تغییر است؛ پیش‌فرض `/tmp/zc300-compare.json` را آزمون PHP می‌سازد. هیچ رمز مدیری در مخزن نیست.

کامپایل دوباره مدل‌ها فقط برای توسعه است:

```bash
ZC_SOURCE_ROOT=/path/to/repo php wp-cli.phar eval-file tools/build-native-models.php --path=/path/to/test-wordpress
```

کامپایلر به DOM و fixture طرح مرجع نیاز دارد؛ هرگز در اجرای عادی قالب/افزونه بارگذاری نمی‌شود. پس از تغییر مدل‌ها، پوشه includes افزونه باید با EmbeddedCore قالب همگام شود.

## محدودیت محیط و موارد ادعانشده

- هشدار nullable در `Elementor/modules/global-classes/atomic-global-styles.php:410` متعلق به Elementor نصب‌شده روی PHP 8.4 باقی است؛ فایل فروشنده تغییر نکرده و هشدار پنهان نشده است.
- MySQL/MariaDB، Safari/Firefox، PHP 8.0 واقعی، ارائه‌دهنده‌های Dynamic Tags در Elementor Pro، SMTP، درگاه پرداخت، بار بالا و ممیزی امنیتی مستقل در این محیط اجرا نشده‌اند.
- دریافت HTTP موفق در محیط آزمایشی یا چند سناریوی مرورگر، تضمین سازگاری همه افزونه‌ها یا پذیرش رسمی مارکت نیست.
- داده Query از رکورد اصلی می‌آید؛ فرم پیش‌فرض سرویس ارسال ایمیل نیست. ساختار تو‌در‌توی نامحدود و Container مستقل برای هر جزء وجود ندارد؛ مرزها در راهنمای نسخه صریح است.
