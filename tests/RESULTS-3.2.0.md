# نتایج اجرای ۳٫۲٫۰

۲۲ اکتبر ۲۰۲۶؛ WordPress 7.1.3، Elementor 4.3.5، WooCommerce 11.2.1، PHP 8.4.27، SQLite و Chromium/Playwright، روی نصب دورریختنی.

## PHP، داده واقعی و سازگاری

| مجموعه اجراشده | نتیجه |
|---|---|
| `native-design.php` | ۲۰۳۵ assertion موفق، ۲۶ مدل؛ فیلدهای واقعی، رسانه Repeater، متن/پیوند/آیکن، هویت، مهاجرت و Query |
| `dynamic-content-3.2.php` | ۵۵ بررسی موفق؛ ۵۳ محصول موقت، پیش‌نویس و محصول مخفی؛ نمایش همه بدون سقف ۵۰، دسته‌های چندریشه/فرزند/نوه، دسته مادر چندانتخابی، فیلتر صحیح، حالت خالی، قیمت Woo، CPT/مقاله و تصویر، صفحات داخلی، سه ویجت واقعی، تبدیل idempotent، حفظ متن، ۱۷ امکان برای یک پلن، حذف/ترتیب و جدایی امکانات پلن‌ها، آواتار، اندازه تصویر و پوشش دمو |
| `wordpress-integration.php` | ۲۳۲ PASS؛ ثبت ویجت، کنترل، خروجی، CPT و درون‌ریزی مجدد بدون افزایش رکوردها |
| `restore-and-identity.php` | ۳۵۳ بررسی موفق؛ هویت، CSS و سازگاری طرح قبلی |
| `professional-inline.php` | ۱۰۰ بررسی موفق |
| `demo-coverage.php` | پوشش هر ۲۲ نوع فعال در صفحه اصلی، صفحات داخلی و قالب‌های هدر/فوتر تایید شد؛ هیروی یکپارچه در دمو نیست |
| `professional-kit.php` | ورود کیت، شش ویجت و تولید CSS موفق |
| `icon-compatibility.php` | ۱۴۷ بررسی روی ۲۳ نوع ویجت؛ آزمون فقط آیکنِ فیلد ثبت‌شده را نرمال می‌داند، نه آرایه دلخواه ناشناخته |

متن/رسانه/پیوند دستی در حالت دستی آزمایش شده‌اند؛ در حالت خودکار، داده محتوا باید از نوشته/CPT/محصول ویرایش شود. کنترل ارتباطی `plan_key` عمداً متن نمایشی نیست و آزمون متن نمایشی به آن تعمیم داده نشده است.

## مرورگر، مدیا، انتشار و تبدیل

`fixture-3.2.php` و `browser-3.2.cjs` روی صفحه اختصاصی قابل حذف اجرا شدند:

- سه ویجت مجزا در خروجی و ترکیب دو ستونه دسکتاپ، تک‌ستونه تبلت و موبایل.
- عرض‌های ۱۴۴۰، ۷۶۸ و ۳۹۰؛ بدون overflow افقی.
- دسته‌های واقعی محصولات منتشرشده، دقیقاً یک فیلتر فعال اولیه، فیلتر و بازنشانی با کلیک واقعی.
- بارگیری واقعی تصاویر شاخص چهار منبع و نسبت اندازه‌گیری‌شده ۱٫۶.
- ویرایش عنوان ویجت مستقل از پنل، ویرایش/افزودن امکان از Repeater بومی.
- انتخاب تصویر مشتری از **کتابخانه رسانه واقعی WordPress**، نه فقط تزریق JSON.
- انتشار واقعی با فرمان ذخیره Elementor، بازکردن frontend و تأیید ماندگاری عنوان، دو امکان و تصویر مشتری.
- اجرای فرم مدیریت «تفکیک هیرو» با نشست مدیر و nonce؛ سه ویجت واقعی پس از تبدیل و حفظ عنوان تایید شد. JSON پشتیبان با نسخه پیش از تبدیل، بایت‌به‌بایت برابر بود.

انتخاب ویجت/بازکردن سربرگ بخش در آزمون خودکار از dispatchEvent استفاده می‌کند تا پوشش خوشامدگویی خارجی Elementor مزاحم نباشد؛ تایپ، دکمه افزودن و کتابخانه رسانه با ورودی واقعی مرورگر انجام شدند. جریان‌ها پس از کامل‌شدن رندر زنده به مرحله بعد می‌روند.

در یکی از اجراهای سریع قبل از اضافه‌شدن انتظار برای رندر، هنگام تعویض پنل/مدیا خطای گذرای `Cannot read properties of null (reading 'select')` دیده شد؛ منشأ دقیق آن تعیین نشد. اجرای مجدد و جریان نهاییِ هماهنگ با رندر بدون خطای JS عبور کردند. این نتیجه، ادعای رفع همه خطاهای احتمالی Elementor نیست.

همچنین `native-browser.cjs` و `professional-browser.cjs` برای inline واقعی، ذخیره/بازخوانی، کنترل مقایسه با اشاره‌گر/کیبورد و موبایل عبور کردند. تصاویر نمونه هیرو در `home-desktop-3.2.png`، `home-768-3.2.png` و `home-390-3.2.png` ثبت شده‌اند.

## بسته و محدودیت‌ها

- هسته مستقل و EmbeddedCore بدون اختلاف؛ bootstrap همسان؛ lint PHP و نحو JS موفق.
- WXR تازه شامل ۶۳ آیتم انتخاب‌شده دمو/منو/پیوست است، بدون QA، localhost یا حساب آزمایشی. بازواردکردن WXR روی نصب کاملاً تازه در این نوبت اجرا نشده است؛ درون‌ریز بومی قالب و کیت Elementor آزمایش شده‌اند.
- بررسی CRC، ریشه صحیح ZIP، نبود ZIP افزونه داخل قالب و SHA-256 انجام شده‌اند.
- این نسخه بنچمارک جدید زمان کل ادیتور ندارد؛ اعداد نسخه ۳٫۱ به ۳٫۲ تعمیم داده نشده‌اند.
- هشدار deprecation مربوط به nullable در `atomic-global-styles.php` خود Elementor/PHP 8.4 در برخی logها باقی است و مخفی نشده است.
- MySQL/MariaDB، Safari/Firefox، PHP 8.0، پرداخت/تحویل فایل واقعی، ترکیب افزونه‌های مشتری، بررسی امنیتی مستقل و تایید رسمی مارکت‌ها در این نوبت آزمایش نشده‌اند. تبدیل استایل‌های سطح ویجت قدیمی باید در staging بازبینی شود.

## بازتولید

روی نصب دورریختنی با قالب/افزونه فعال و WooCommerce، مجموعه‌های PHP با `wp eval-file tests/نام‌آزمون.php` اجرا می‌شوند. آزمون داده موقت، رکوردها و دسته‌های خود را در finally حذف می‌کند.

برای مرورگر ابتدا `fixture-3.2.php` و در صورت نیاز `hero-upgrade-fixture.php` را اجرا کنید؛ شناسه‌ها را در `ZC_TEST_PAGE_ID` و `ZC_TEST_MIGRATION_PAGE_ID` بگذارید. `ZC_TEST_BASE_URL`، `ZC_TEST_ADMIN_USER` و `ZC_TEST_ADMIN_PASSWORD` متغیرهای محیطی‌اند؛ رمز در مخزن نیست. Playwright و Chromium لازم‌اند. آزمون مرورگر صفحه fixture را **منتشر و ویرایش** می‌کند؛ روی صفحه مشتری اجرا نکنید.

برای بازسازی مدل‌ها پس از compiler قدیمی، `python tools/upgrade-native-models.py` را اجرا و سپس includes را به EmbeddedCore همگام کنید. ابزار `portable-demo-export.py` برای آماده‌سازی WXR، ورودی فایل صادرات WP-CLI و کتابخانه توسعه‌ای lxml می‌خواهد؛ Python در اجرای قالب/افزونه لازم نیست.
