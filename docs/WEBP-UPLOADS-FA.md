# تبدیل خودکار آپلودهای جدید به WebP — 4.0.0-rc.3

## نصب و تنظیمات

ابتدا از سایت و uploads پشتیبان بگیرید و روی staging امتحان کنید. قالب `zarincode` و افزونه همراه `zarincode-core` نسخه rc.3 را به‌روز کنید؛ مسئول تبدیل، **افزونه** است و به فعال بودن قالب وابسته نیست. از بخش «بهینه‌سازی تصاویر WebP» در پنل قالب:

| گزینه | پیش‌فرض | بازه/اثر |
|---|---|---|
| تبدیل خودکار | روشن | فقط آپلودهای جدید محلی از مسیر استاندارد وردپرس |
| کیفیت | ۸۲ | ۵۰ تا ۱۰۰؛ ۱۰۰ الزاماً lossless نیست |
| فقط خروجی کوچک‌تر | روشن | خروجی مساوی/بزرگ‌تر کنار گذاشته می‌شود |
| حد حجم ورودی | ۲۵ MiB | ۱ تا ۱۰۰ MiB؛ نه تغییر upload_max_filesize سرور |
| حد پیکسل | ۴۰ مگاپیکسل | ۱ تا ۸۰؛ تصویر بزرگ‌تر بدون تبدیل باقی می‌ماند |

**تبدیل موفق فایل ورودی را جایگزین می‌کند؛ نسخه JPEG/PNG اولیه نگه‌داری نمی‌شود.** این تصمیم تنها پس از اعتبارسنجی و بازخوانی کامل خروجی اجرا می‌شود. اگر نگهداری اصل لازم است، پیش از آپلود نسخه پشتیبان مستقل داشته باشید یا قابلیت را خاموش کنید. رسانه‌های قبلی و نشانی‌های درج‌شده قبلی بازنویسی نمی‌شوند؛ ابزار تبدیل دسته‌جمعی اضافه نشده است.

## پوشش واقعی، نه وعده «همه فرمت‌ها»

- JPEG، PNG و GIF ثابت در صورت پشتیبانی ویرایشگر سرور قابل تبدیل‌اند. PNG/GIF پالت‌دار برای GD بدون تغییر ابعاد به truecolor نرمال می‌شوند. شفافیت حفظ و جهت EXIF در JPEG توسط API وردپرس اصلاح می‌شود.
- BMP، TIFF، AVIF، HEIC و HEIF فقط در صورت مجاز بودن نوع ورودی در وردپرس و داشتن decoder/encoder مناسب قابل بررسی‌اند؛ TIFF/AVIF/HEIC/HEIF علاوه بر آن نیازمند تأیید تک‌فریمی بودن توسط Imagick هستند. وجود نام فرمت در فهرست، تضمین قابلیت سرور نیست.
- GIF متحرک، APNG و JPEG دارای شاخص چندتصویری MPO تبدیل نمی‌شوند. ساختار GIF/PNG/JPEG با پیمایش محدود بررسی می‌شود؛ موارد نامعتبر/نامطمئن حفظ می‌شوند. خروجی چندصفحه‌ای با تبدیل به تک‌فریم از دست نمی‌رود.
- WebP موجود دوباره فشرده نمی‌شود. SVG، PDF، ICO و فرمت‌های خارج از فهرست تغییر نمی‌کنند. هیچ MIME تازه‌ای به مجوزهای آپلود اضافه نمی‌شود.
- فایل خارج از uploads، symlink/stream، URL تغییرکرده توسط ذخیره‌ساز خارجی و فایل غیرمحلی کنار گذاشته می‌شود. تبدیل/همگام‌سازی مستقیم رسانه S3 یا CDN امضاشده پیاده نشده است؛ سازگاری تمام افزونه‌های offload تضمین نشده است.
- این تبدیل lossy است و می‌تواند metadata اصلی را طبق رفتار codec وردپرس حذف کند. «کمترین حجم مطلق»، «بدون افت» و «تبدیل هر قالب» تضمین نشده‌اند. کاهش حجم هر تصویر متفاوت است؛ تنظیم only-smaller از افزایش حجم فایل اصلی جلوگیری می‌کند، نه لزوماً مجموع تمام اندازه‌های جانبی.

## مسیر اجرا و ایمنی

هوک مشترک `wp_handle_upload` با اولویت ۲۰، پیش از ایجاد attachment، برای upload و sideload استفاده می‌شود؛ فایل، URL و MIME هم‌زمان اصلاح می‌شوند. سپس خود وردپرس metadata، thumbnail، اندازه‌های میانی و srcset را تولید می‌کند؛ محدودیت اندازه بزرگ و `-scaled` وردپرس تغییر نکرده است. بارگذاری‌هایی که این مسیر را دور می‌زنند یا فایل‌های صرفاً کپی‌شده روی سرور پوشش داده نمی‌شوند.

پیش از decode، حجم، پیکسل و برآورد محافظه‌کارانه حافظه PHP کنترل می‌شود. این کنترل تضمین جلوگیری از همه OOMهای سیستم/Imagick نیست. نام مقصد با رزرو انحصاری ساخته می‌شود؛ فایل WebP موجود بازنویسی نمی‌شود. ذخیره با MIME مشخص، بررسی مسیر/نوع واقعی/ابعاد/حجم، سپس **decode دوباره خروجی** انجام می‌شود. اگر خروجی معتبر یا کوچک‌تر نباشد، یا حذف اصل توسط وردپرس منع شود، خروجی موقت پاک و ورودی حفظ می‌شود. حذف اصل آخرین مرحله commit است. خدمت ابری، جدول جدید، cron یا پردازش رسانه قدیمی وجود ندارد.

کیفیت WebP از `wp_editor_set_quality` اعمال می‌شود؛ هنگام روشن بودن ماژول، مشتقات و ویرایش‌های WebP وردپرس نیز از همین مقدار استفاده می‌کنند؛ کیفیت JPEG تغییر نمی‌کند. کلیدهای تنظیمات علاوه بر پنل، داخل افزونه هم محدود و اعتبارسنجی می‌شوند. وضعیت قابلیت‌ها و تنظیمات بدون مسیر فایل/داده کاربر در Site Health قرار می‌گیرد.

توسعه‌دهندگان می‌توانند با `zarincode_webp_upload_allowed` (آرگومان‌ها: allowed، upload، context) مورد خاصی را مستثنا کنند. اکشن `zarincode_webp_result` فقط یک reason code محدود دارد؛ شامل نام/مسیر/اطلاعات کاربر نیست و به‌طور پیش‌فرض هیچ لاگ پایداری ذخیره نمی‌کند. خطای observer مانع آپلود نمی‌شود.

## بازتولید آزمون مستقل

PHP 8+ با GD/WebP لازم است. دو کلاس رسمی زیر را در پوشه موقت خارج از مخزن دریافت کنید؛ سورس آن‌ها همراه محصول بسته‌بندی نمی‌شود:

- `wp-includes/class-wp-image-editor.php`
- `wp-includes/class-wp-image-editor-gd.php`
- مخزن `WordPress/WordPress`، commit ثابت `19c5d35a3df0a56d92a0f8d954bc5b0b7dac8411`.

الگوی دریافت از GitHub contents API، با `Accept: application/vnd.github.raw+json`:
`https://api.github.com/repos/WordPress/WordPress/contents/wp-includes/class-wp-image-editor.php?ref=19c5d35a3df0a56d92a0f8d954bc5b0b7dac8411`

```sh
ZARINCODE_QA_WP_EDITOR=/tmp/wp-editors php tools/qa-webp-uploads.php
```

این آزمون codec و کلاس‌های editor واقعی دارد، اما APIهای محیط وردپرس در آن double هستند؛ جای آزمون دیتابیس نیست.

## آزمون یکپارچه واقعی

فایل `tools/qa-webp-wordpress.php` فقط روی وردپرس **مصرف‌شدنی آزمایشی** اجرا شود؛ به کاربر administrator موجود، GD/WebP، افزونه همراه فعال و این ثابت‌ها در wp-config نیاز دارد:

```php
define('WP_ENVIRONMENT_TYPE', 'local');
define('ZARINCODE_DISPOSABLE_QA', true);
```

```sh
wp --path=/tmp/disposable-wp eval-file /path/to/Zarincode-1/tools/qa-webp-wordpress.php
```

این آزمون موقتاً تنظیمات را تغییر می‌دهد، PNG و WebP آزمایشی را با `media_handle_sideload` وارد می‌کند، attachment/MIME/metadata/subsizes/URL/srcset، خاموش‌سازی و عدم بازفشرده‌سازی WebP را بررسی می‌کند؛ در finally رسانه‌های ساخته‌شده را حذف و تنظیمات و کاربر را برمی‌گرداند. روی سایت واقعی اجرا نکنید. این آزمون UI مرورگر یا درخواست multipart از مرورگر نیست.

نتیجه واقعی این چرخه و محدودیت‌ها: [گزارش آزمون](audits/2026-10-28-WEBP-FA.md).
