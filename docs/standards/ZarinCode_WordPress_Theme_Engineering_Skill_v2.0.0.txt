بخش ۱ ـ مأموریت و فلسفه اصلی Skill
================================================================

۱.۱. هدف
این Skill برای هدایت یک سیستم هوش مصنوعی در طراحی و توسعه قالب‌های حرفه‌ای، تجاری، امن، سریع، توسعه‌پذیر و قابل فروش وردپرس ایجاد شده است. هدف صرفاً تولید یک قالب زیبا نیست؛ هدف ساخت یک محصول نرم‌افزاری کامل است که در پروژه‌های مختلف با هویت بصری متفاوت قابل استفاده باشد، از قابلیت‌های استاندارد وردپرس و افزونه‌های هدف پشتیبانی کند، تجربه طراحی حرفه‌ای در Elementor و Elementor Pro ارائه دهد، تمام ویجت‌های استاندارد را با هویت بصری اختصاصی قالب نمایش دهد، ماژولار و توسعه‌پذیر باشد، امنیت و عملکرد و SEO و دسترس‌پذیری مناسبی داشته باشد، برای عرضه تجاری آماده باشد و مستندات و تست‌های قابل نگهداری داشته باشد.

۱.۲. اصول غیرقابل‌چشم‌پوشی
- کیفیت عملکردی بر سرعت تولید کد اولویت دارد.
- کدنویسی باید واقعی، قابل اجرا و قابل تست باشد.
- قابلیت نمایشی نباید به‌عنوان قابلیت عملیاتی معرفی شود.
- کد غیرضروری نباید در Frontend بارگذاری شود.
- امنیت نباید صرفاً به JavaScript سمت کاربر وابسته باشد.
- تمام قابلیت‌ها باید معماری و مسئولیت مشخص داشته باشند.
- تمام ویجت‌های Elementor و Elementor Pro باید از نظر بصری با قالب هماهنگ شوند.
- هیچ ویجت پشتیبانی‌شده‌ای نباید بدون بررسی با ظاهر پیش‌فرض و ناسازگار باقی بماند.
- تمام متن‌های ثابت باید از سیستم استاندارد ترجمه وردپرس استفاده کنند.
- موتور مدیریت ترجمه موازی با WPML ساخته نشود.
- موتور SEO موازی با Yoast SEO یا Rank Math ساخته نشود.
- کدهای اصلی وردپرس، Elementor و WooCommerce مستقیماً دست‌کاری نشوند.
- از APIهای عمومی و مستندشده استفاده شود.
- هیچ تضمین غیرواقعی درباره رتبه گوگل، امتیاز ابزارهای سنجش یا ظرفیت سرور داده نشود.
- پیش از انتشار، تست عملکرد، امنیت، واکنش‌گرایی و سازگاری الزامی است.

۱.۳. استقلال از مدل هوش مصنوعی
این Skill باید مستقل از مدل، شرکت سازنده یا محیط اجرای هوش مصنوعی باشد. هر مدل دریافت‌کننده باید بتواند نیازمندی‌ها را استخراج کند، معماری طراحی کند، ساختار فایل‌ها را بسازد، کد Theme و Companion Plugin را تولید کند، ویجت اختصاصی بسازد، استایل تمام ویجت‌های Elementor را پیاده‌سازی کند، تست بنویسد و اجرا کند، خطاها را اصلاح کند و مستندات و خروجی قابل ارزیابی تحویل دهد. هیچ بخش ضروری نباید به قابلیت اختصاصی یک مدل وابسته باشد.

۲.۱. معماری Hybrid: Theme + Companion Plugin

وظایف Theme:
- ظاهر و هویت بصری، ساختار صفحات و Templateها، Header و Footer.
- ساختار نمایش محتوا، تنظیمات پایه، Design Tokens، Typography و رنگ‌ها.
- استایل عمومی، ساختار نمایش نوشته‌ها و برگه‌ها.
- استایل و Templateهای WooCommerce.
- سازگاری Gutenberg و محل‌های رسمی نمایش Elementor.
- Responsive Layout و تنظیمات ظاهری و چیدمان.

وظایف Companion Plugin:
- ویجت‌های اختصاصی Elementor و Dynamic Tags.
- قابلیت‌های اختصاصی Gutenberg.
- Feature Registry و Feature Manager.
- سرویس‌های تجاری، CPT و Taxonomy در صورت نیاز.
- REST API، پردازش پس‌زمینه، Migration و Integration.
- قابلیت‌های توسعه‌پذیر، داده‌ها و تنظیمات ماندگار و منطق عملکردی اختصاصی.

۲.۲. جداسازی مسئولیت‌ها
منطق پرداخت، حساب کاربری و عملیات حساس نباید به Theme وابسته باشد. پردازش سنگین نباید در فایل‌های نمایش قالب اجرا شود. داده‌های ماندگار نباید با تغییر Theme از بین بروند. ویجت‌های اختصاصی و سرویس‌های وابسته باید در Companion Plugin قرار گیرند.

۲.۳. استقلال نصب و حذف
- Theme بدون Companion Plugin باید ساختار پایه وردپرس را نمایش دهد.
- امکانات وابسته در نبود افزونه همراه باید وضعیت مشخصی داشته باشند.
- حذف Theme نباید اطلاعات ماندگار Plugin را حذف کند.
- حذف Plugin نباید داده‌های کاربر را ناخواسته پاک کند.
- حذف داده‌ها باید شفاف و مطابق تنظیمات کاربر و الزامات حریم خصوصی باشد.

۴.۳. Typography
برای H1 تا H6، Body، Paragraph، Caption، Label، Button، Navigation، Form Fields، Product Titles، Price، Meta Information، Blockquote، Code، Lists و Tables استایل مشخص تعریف شود.

۴.۴. Responsive Design
پشتیبانی واقعی از Desktop، Laptop، Tablet و Mobile الزامی است. ساختار ستون‌ها، فاصله‌ها، فونت، منو، تصاویر، فرم‌ها، جداول، اسلایدرها، Popupها، فروشگاه و صفحات ورود و حساب کاربری در اندازه‌های مختلف بررسی شوند.

۴.۵. RTL و LTR
فارسی و عربی باید RTL واقعی و انگلیسی LTR واقعی داشته باشند. صرفاً معکوس‌کردن چند ویژگی CSS کافی نیست. Logical CSS Properties، ترتیب آیکون و متن، منوها، فرم‌ها، Breadcrumbs، جداول، اسلایدرها، نمودارها، دکمه‌ها و انیمیشن‌های جهت‌دار باید بررسی شوند.

۵.۶. Elementor Styling Layer
یک لایه مستقل برای استایل‌دهی ایجاد شود که:
- تمام ویجت‌ها را با Design Tokens هماهنگ کند.
- استایل‌های پایه و خانواده ویجت‌ها را تعریف کند.
- Editor و Frontend را هماهنگ کند.
- RTL/LTR را پشتیبانی کند.
- از تداخل CSS جلوگیری کند.
- تنظیمات Style خود Elementor را حفظ کند.
- سازگاری نسخه‌ای داشته باشد.

معماری CSS:
- فایل‌های CSS ماژولار باشند.
- استایل ویجت‌ها در فایل مستقل یا خانواده مشخص قرار گیرد.
- Selectorها تا حد امکان به محدوده ویجت و قالب محدود باشند.
- از Selector عمومی مخرب اجتناب شود.
- !important فقط با دلیل فنی مستند استفاده شود.
- فایل‌های Elementor تغییر داده نشوند.
- ساختار خصوصی و مستندنشده وابستگی اصلی نباشد.
- CSS تکراری بارگذاری نشود.

هماهنگی Editor و Frontend:
- فونت و رنگ در Editor صحیح باشد.
- پیش‌نمایش Responsive صحیح باشد.
- کنترل‌های ویرایشگر مختل نشوند.
- UI خود Elementor آسیب نبیند.
- تغییرات زنده قابل مشاهده باشند.
- تفاوت غیرموجه Editor و Frontend وجود نداشته باشد.

حفظ آزادی طراحی:
استایل قالب هویت بصری پایه را فراهم کند، اما تنظیمات مجاز Elementor را محدود نکند. در صورت پشتیبانی ویجت، Typography، Color، Background، Border، Shadow، Spacing، Alignment، Width/Height، Responsive Controls، Motion Effects، Global Colors، Global Fonts و Site Settings باید قابل استفاده بمانند.

۵.۸. ویجت‌های اختصاصی قالب
علاوه بر استایل‌دهی تمام ویجت‌های استاندارد، هر قالب باید ویجت‌های اختصاصی مورد نیاز خود را داشته باشد. این ویجت‌ها در Companion Plugin قرار می‌گیرند و می‌توانند شامل Layout، Header، Footer، Blog، Marketing، Landing Page، Media، Form، Navigation، Dynamic Content، Data Visualization، WooCommerce، Social و Utility باشند. ویجت‌ها باید از Dynamic Tags، کنترل‌های استاندارد Elementor، Responsive Controls و ترجمه پشتیبانی کنند.
