# بهبود موبایل و PWA — ۲۰۲۶-۱۰-۲۸

## دامنه بررسی و تغییر

ساختار راه‌اندازی قالب و هسته، مدیریت Assets، هدر و منوی قالب، رویدادهای هدر native المنتور، استایل‌های responsive، حساب کاربری، صفحه محصول، تجربه مطالعه و زیرساخت QA بررسی شدند. استایل‌های واکنش‌گرای موجود حفظ و تکمیل شده‌اند؛ بازطراحی همه مدل‌های JSON المنتور یا ممیزی خط‌به‌خط تمام مخزن انجام نشده است.

- کنترلر مشترک منوی موبایل برای هدر قالب و دکمه‌های هدر native؛ حذف مسیر متداخل قدیمی.
- نقش dialog، aria-expanded/controls، غیرفعال‌کردن پس‌زمینه با inert، حبس فوکوس، Escape، بازگردانی فوکوس و حفظ overflow قبلی بدنه.
- زیرمنوهای دسترس‌پذیر و بسته‌شدن منو پس از انتخاب لینک؛ پشتیبانی از RTL و LTR.
- کنترل‌های لمسی ۴۴ پیکسلی، ورودی‌های ۱۶ پیکسلی برای جلوگیری از زوم ناخواسته iOS، safe area و ارتفاع پویا.
- اصلاح نمایش موبایل فرم‌ها، جدول‌های فروشگاه، کوپن، سفارش، حساب، پنجره‌ها، سربرگ باریک و حالت افقی.
- حفظ سیاست نمایش همیشگی عنوان حساب با انتقال اکشن‌های هدر به ردیف مجزا در عرض بسیار کم.
- نسخه‌گذاری دارایی‌های تغییریافته برای جلوگیری از باقی‌ماندن کنترلر قدیمی در کش مرورگر.

## معماری PWA

مالک قابلیت، افزونه `zarincode-core` است؛ قالب فقط ارائه موبایل را مدیریت می‌کند.

- Manifest: `/?zc_pwa=manifest`
- Worker: `/?zc_pwa=worker`
- صفحه آفلاین: `/?zc_pwa=offline`

این URLها نسبت به `home_url('/')` ساخته می‌شوند؛ با نصب زیرشاخه‌ای و پیوند یکتای ساده سازگارند و به flush rewrite نیاز ندارند. Worker با MIME جاوااسکریپت، `Service-Worker-Allowed` محدود به مسیر سایت، هدرهای بدون کش و nosniff ارائه می‌شود. نام کش برای هر سایت جداست.

Manifest دارای scope، start_url، شناسه پایدار، زبان/جهت سایت، standalone و آیکن‌های PNG واقعی ۱۹۲/۵۱۲، maskable و Apple ۱۸۰ است. آیکن پیش‌فرض مونوگرام ZC است؛ با تغییر برند باید جایگزین شود.

### سیاست آفلاین و امنیت

عمداً **هیچ صفحه بازدیدشده‌ای در کش ذخیره نمی‌شود**. حساب، سفارش، سبد، پرداخت، REST، AJAX، درخواست POST، توکن‌ها و محتوای شخصی آفلاین نمی‌شوند. صفحات همیشه از شبکه خوانده می‌شوند؛ فقط هنگام شکست شبکه، صفحه عمومی و مستقل آفلاین نمایش داده می‌شود. خطاهای HTTP سرور با صفحه آفلاین پوشانده نمی‌شوند.

تنها صفحه آفلاین ثابت و آیکن‌های مشخص‌شده در allowlist در CacheStorage نگهداری می‌شوند. صفحه آفلاین بدون فونت، CDN یا درخواست خارجی است. پیام صریح دارد که نمایش آن نشانه موفقیت پرداخت نیست. هیچ همگام‌سازی پس‌زمینه یا تکرار خودکار سفارش انجام نمی‌شود.

Worker جدید کش‌های نسخه قبلی همین سایت را پاک می‌کند؛ کش افزونه‌های دیگر حذف نمی‌شود. نصب worker نامرتبط موجود بازنویسی نمی‌شود. به‌روزرسانی نیاز به اقدام کاربر دارد و هیچ فرم یا صفحه پرداختی خودکار reload نمی‌شود. اگر worker متعلق به افزونه دیگری دارید، ابتدا مالکیت PWA را تعیین کنید.

### نصب و پیکربندی

۱. قالب و افزونه تغییرکرده را با هم روی **staging** به‌روز کنید؛ کش/CDN و کش دارایی‌های تولیدشده المنتور را پاک کنید.
۲. HTTPS معتبر الزامی است (localhost فقط برای آزمون است). endpointهای بالا باید بدون redirect، صفحه ورود، challenge امنیتی یا MIME نادرست در دسترس باشند. در CDN این سه endpoint را از full-page cache خارج کنید.
۳. Chrome/Edge در صورت فراهم‌بودن معیارهای نصب، رویداد نصب را عرضه می‌کنند؛ دکمه نصب تنها پس از آن نمایش داده می‌شود. زمان پیشنهاد نصب در کنترل مرورگر است.
۴. در Safari/iOS راهنمای Share → Add to Home Screen نمایش داده می‌شود؛ نصب خودکار یا دیالوگ بومی Chrome در iOS وجود ندارد.
۵. عنصر اختیاری `[data-zc-pwa-install]` می‌تواند برای راهنمای نصب استفاده شود. پیشنهاد نصب در جریان عادی سند است تا روی دکمه پرداخت شناور نشود؛ بستن آن تا پایان نشست حفظ می‌شود.
۶. نام و زبان برنامه از تنظیمات عمومی وردپرس گرفته می‌شود.

غیرفعال‌سازی با فیلتر وردپرس (در افزونه اختصاصی سایت):

```php
add_filter( 'zarincode_pwa_enabled', '__return_false' );
```

endpoint worker را حذف/مسدود نکنید: worker غیرفعال در بررسی به‌روزرسانی بعدی مرورگر، کش‌های متعلق به خودش را پاک و ثبت خودش را لغو می‌کند. این فرایند فوری و از راه دور روی تمام دستگاه‌های آفلاین نیست. در صورت حذف کامل افزونه، پیش از حذف اجازه دهید worker غیرفعال به کاربران برسد.

## شواهد آزمون

- ۷۲ assertion مرورگری موفق در Chromium headless: عرض‌های ۳۲۰، ۳۶۰، ۳۹۰، ۴۳۰، ۷۶۸، ۱۰۲۴، ۱۴۴۰؛ عدم overflow نمونه کنترل‌شده، فوکوس/Tab/Shift+Tab، Escape، بازگشت فوکوس، inert، ARIA و زیرمنو، LTR، برچسب حساب همیشگی و ارتفاع کم.
- ثبت واقعی Service Worker روی HTTP loopback در مسیر `/site/`، fallback آفلاین، بازگشت آنلاین، عدم کش HTML خصوصی/مسیرهای خرید، بقای کش نامرتبط، حذف کش قدیمی و بازنشستگی worker غیرفعال.
- ۸۴ فایل PHP با parser سازگار با PHP 8.4 بدون خطای نحوی parse شدند. PHP CLI در محیط موجود نبود؛ **این نتیجه جایگزین اجرای PHP یا آزمون WordPress نیست**.
- کنترل معماری scoped موجود پروژه موفق؛ ۶ تست قرارداد ممیزی و ۶ تست محافظ ساخت بسته موفق.
- syntax check جاوااسکریپت و `git diff --check` موفق.

اجرای مجدد:

```sh
npm ci --prefix tools/browser --ignore-scripts
npm exec --prefix tools/browser -- playwright install --with-deps chromium --only-shell
NODE_PATH=tools/browser/node_modules node tools/qa-mobile-pwa.cjs
```

اسکریپت آزمون برای اجرای محلی/CI موجود است؛ افزودن مرحله جدید به GitHub Actions به دلیل نبود مجوز workflows در اتصال فعلی، در این تغییر انجام نشده است. موفقیت اجرای remote CI ادعا نشده است. harness از فایل‌های واقعی CSS/JS و endpoint شبیه‌سازی‌شده با worker واقعی استفاده می‌کند؛ از WordPress، دیتابیس، رندر واقعی قالب PHP یا محتوای واقعی المنتور استفاده نمی‌کند.

## گیت‌های باقی‌مانده پیش از انتشار عمومی

- نصب واقعی WordPress + Elementor + WooCommerce؛ آزمایش صفحه اصلی و تمام صفحات/قالب‌های سفارشی در عرض‌های فوق؛ متن‌های طولانی، بدون تصویر و بزرگنمایی ۲۰۰٪.
- آزمون خرید مهمان و عضو، درگاه sandbox، بازگشت درگاه، کوپن، تغییر تعداد، ثبت‌نام، بازیابی رمز و نشست کاربر؛ هیچ پرداخت واقعی با این تغییر آزموده نشده است.
- Android Chrome و Safari واقعی iPhone/iPad: نصب، اجرای standalone، keyboard، landscape، safe area، آفلاین و ارتقای نسخه.
- DevTools Application: manifest معتبر، scope درست، CacheStorage فقط شامل shell/آیکن‌ها، عدم تداخل با افزونه کش/PWA دیگر.
- اجرای واقعی PHP lint، آزمون‌های ادغام موجود، کنترل ظاهر تمام ویجت‌های شخصی‌سازی‌شده و ممیزی دسترس‌پذیری روی staging.

بنابراین این تغییر پیاده‌سازی و رگرسیون‌های مستقل آزموده‌شده است، نه ادعای تأیید کامل همه صفحات سایت یا آمادگی انتشار بدون staging.
