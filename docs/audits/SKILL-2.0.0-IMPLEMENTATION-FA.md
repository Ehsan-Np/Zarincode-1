# تطبیق اجرایی Skill 2.0.0 — مرحلهٔ زیرساخت

**وضعیت انتشار تجاری: مسدود — این تغییرات گواهی انطباق کامل نیستند.**

نسخهٔ سورس این مرحله `3.9.0-dev` است؛ بسته‌های پایدار موجود در `packages/` همچنان 3.7.5 هستند و عمداً جایگزین نشده‌اند. ارتقا به شمارهٔ توسعه به معنی بازگرداندن طراحی ردشدهٔ 3.8 نیست. قالب محصول، سایدبار و کارت‌های تأییدشده بازطراحی نشده‌اند. هیچ تغییر یا استقراری روی سایت اصلی انجام نشده است.

## تغییرات واقعی

- فیلتر مشترک `pre_update_option_zarincode_opt` برای مسیرهای ذخیرهٔ بومی، Redux و import: اعتبارسنجی switch/select، حفظ کلیدهای نامرتبط، محدودکردن تغییر اسکریپت به `unfiltered_html` و جلوگیری از بستن عنصر style با CSS واردشده. این کار sandbox عمومی CSS یا جایگزین احراز مجوز endpoint نیست.
- مالکیت اسکیما برای Yoast/Rank Math/AIOSEO؛ جلوگیری از تولید اسکیما عمومی قالب هنگام حضور مالک سئو. رتبه‌های واقعی قابل‌نمایش مقاله حذف نشده‌اند؛ aggregateRating مقاله به‌صورت پیش‌فرض خاموش است. ادعای نمایش ستاره در نتایج گوگل وجود ندارد.
- حذف اجبار سراسری RTL و استثنای زبانی مبتنی بر slug؛ تعیین جهت با locale وردپرس و تبدیل اعداد فارسی فقط در RTL. این اصلاح، اثبات بازبینی کامل LTR تمام مؤلفه‌ها نیست.
- `theme.json`، استایل و فونت محلی ویرایشگر، CSS مشروط بلوک‌ها و الگوی بومی معرفی آژانس. دامنهٔ استایل‌های جدید بلوک‌ها محدود است تا ویجت‌های تأییدشده بازنویسی نشوند.
- ثبت محل‌های رسمی Elementor Pro؛ اولویت template رسمی هدر/فوتر بر builder قدیمی و fallback قالب. builder جایگزین تنها در صورت نیاز رندر می‌شود.
- Feature Registry/Manager اولیه برای **سه خانوادهٔ ویجت اختصاصی**: ۱۷ بومی، ۳ استودیو، ۶ حرفه‌ای. بررسی dependency/conflict/cycle، حفظ تنظیمات هنگام خاموش‌کردن و پاک‌سازی کش CSS المنتور در تغییر وضعیت. خاموش‌شدن بومی، دو خانوادهٔ وابسته را هم متوقف می‌کند. همهٔ سرویس‌های قدیمی هنوز به این مدیر مهاجرت نکرده‌اند.
- کنترل‌های این خانواده‌ها در همان schema مشترک بومی/Redux و همان منوی اختصاصی قرار دارند؛ بخش هویت بصری همچنان بخش پیش‌فرض است. کنترل‌های امنیت پایه خارج از این سوییچ‌ها هستند.
- `wpml-config.xml` برای CPT/taxonomy/meta و بخشی از فیلدهای بومی و repeater المنتور؛ `_id` ترجمه نمی‌شود. پیکربندی تمام ویجت‌ها، به‌خصوص page-section شرطی و خانواده‌های حرفه‌ای/استودیو، کامل نشده است.
- استخراج POT با WP-CLI و PO/MO فارسی برای رشته‌های استخراج‌پذیر فعلی. بسیاری از رشته‌های قدیمی هنوز gettext نشده‌اند؛ وجود فایل ترجمه نشانهٔ کامل‌بودن localization نیست.

## محدودهٔ شواهد

گزارش‌های JSON مجاور این سند، نتایج واقعی همین مرحله را نگه می‌دارند. سورس آزمون‌ها در `tools/qa-skill-foundations.php` و `tools/qa-skill-browser.cjs` است. آزمون‌ها تنها روی نصب local با نشانگر صریح محیط دورریختنی مجاز به تغییر تنظیمات هستند.

- نصب مجزای وردپرس و MariaDB واقعی؛ نسخه‌های دقیق در `SKILL-2.0.0-FOUNDATIONS.json` ثبت شده‌اند.
- ۲۴ assertion زیرساخت: resolver، ثبت/حذف خانواده‌های ۲۶ ویجت، حفظ تنظیمات، محافظت اسکریپت، CSS، مالکیت Yoast با fixture، پالت، الگو و جهت انگلیسی. fixture مالکیت Yoast جای اجرای واقعی تمام افزونه‌های سئو نیست.
- فهرست **۲۲۰ نوع ویجت نصب‌شده** شامل ۲۶ اختصاصی؛ وضعیت editor/frontend/a11y/visual تک‌تک ویجت‌ها عمداً `not_tested` است. فهرست‌برداری مساوی پوشش ظاهری ۱۹۴ ویجت دیگر نیست.
- lint تعداد ۹۱ فایل PHP موفق بوده است؛ این عدد شامل نسخه‌های mirror است، نه ۹۱ مؤلفهٔ مستقل.
- آزمون Chromium در ۲۴ ترکیب (خانه، برگهٔ بلوکی، محصول و خدمت × عرض‌های ۳۲۰/۷۶۸/۱۴۴۰ × فارسی/انگلیسی) با پاسخ ۲۰۰، جهت صحیح، skip-link، main و بدون overflow افقی موفق شد. CSS بلوک در fixture بلوکی بارگذاری شد. در خاموشی کامل، تعداد ویجت اختصاصی صفحه و handleهای asset اختصاصی بررسی‌شده صفر بود. این آزمون بازبینی بصری تطبیقی، keyboard یا WCAG نیست. اولین اجرای نامعتبر به علت URL اشتباه فایل‌های محیط QA کنار گذاشته شد؛ خطای محیط نباید شاهد شکست یا موفقیت محصول حساب شود.
- بستهٔ Yoast Premium دارای برچسب شخص ثالث اجرا نشده است. Elementor/Pro/Redux/Woo از نسخه‌های ثبت‌شدهٔ مخزن معرفی‌شدهٔ کاربر در محیط مجزا اجرا شدند؛ این موضوع اصالت ناشر یا تأیید تجاری بسته‌ها را اثبات نمی‌کند.

### خطاهای مشاهده‌شدهٔ محیط سازگاری

PHP 8.4 در Elementor نصب‌شده هشدار nullable-deprecation ایجاد کرد. همچنین هشدار `Attempt to read property ID on null` از مسیر document المنتور در رندر fixture دیده شد؛ علت ریشه‌ای نسبت به دادهٔ demo/فراخوان قالب/نسخهٔ افزونه هنوز تشخیص داده نشده و به‌اشتباه صرفاً تقصیر افزونه اعلام نمی‌شود. فعال‌سازی Woo از CLI هم‌زمان با Elementor خطا داد؛ فعال‌سازی مجدد با skip موقت Elementor موفق شد. این‌ها اجازهٔ ادعای «سازگاری بی‌خطا» نمی‌دهند.
