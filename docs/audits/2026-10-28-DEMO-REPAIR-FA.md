# ترمیم دمو — 4.0.0-rc.4

## علت و اصلاح

- بسته WXR شامل ۷۱ مقاله بود، اما درون‌ریز بومی هنوز تنها شش نوشته قدیمی `Service_Demo::blog()` را می‌ساخت. اکنون generator از همان WXR یک JSON همسان تولید می‌کند و هر دو مسیر native/OCDI از importer مشترک استفاده می‌کنند؛ افزونه OCDI یا extension XML برای مسیر native لازم نیست.
- تعداد مقالات نشان‌دار: طراحی ۱۰، سئو ۱۰، تولید محتوا ۵، وردپرس ۱۲، امنیت ۲۲، سرعت/بهینه‌سازی ۱۲؛ مجموع ۷۱. مقالات قبلی مشتری و شش نوشته تاریخی احتمالی حذف نمی‌شوند؛ بنابراین کل نوشته‌های سایت لزوماً ۷۱ نیست.
- تصاویر محلی با API استاندارد `media_handle_sideload` ثبت و metadata/subsizes واقعی تولید می‌شوند. با WebP جدید نیز سازگار است؛ MIME خروجی بر اساس نتیجه واقعی وردپرس ثبت می‌شود. hash منبع از ساخت تصویر تکراری در اجراهای بعدی جلوگیری می‌کند. نام فایل مقصد ثابت/قابل بازنویسی نیست.
- تصویر شاخص سالم حفظ می‌شود؛ تصویر حذف‌شده/attachment شکسته ترمیم می‌شود. همین مسیر برای تصاویر خدمات، پروژه‌ها، محصولات و نوشته‌های تاریخی نشان‌دار نیز استفاده می‌شود. چهار تصویر موجود دمو بین مقالات چرخشی مشترک‌اند؛ ۷۱ تصویر اختصاصی جدید تولید نشده است.
- slug نوشته مشتری دلیل مجاز برای بازنویسی نیست؛ فقط مقالات دارای نشان دمو به‌روزرسانی می‌شوند. لینک داخلی مقالات با home_url سایت مقصد هماهنگ می‌شود.
- callback بسته مستقل مقالات دیگر `seed_all` اجرا نمی‌کند؛ تنظیمات قالب، برگه‌ها و فروشگاه بی‌جهت بازنشانی نمی‌شوند.
- یک require غیرضروری مجموعه کلاس‌های Elementor، کل درون‌ریزی را در نبود Elementor متوقف می‌کرد؛ حذف شد و مدل‌های داده مستقل autoload می‌شوند. برای ویرایش/نمایش المنتوری همچنان نصب Elementor لازم است؛ سازگاری تمام نسخه‌های آن اینجا تأیید نشده است.
- صفحه native به عنوان، یک پاراگراف استاندارد، فرم انتخاب بخش و پیام نتیجه خلاصه شد؛ تبلیغات، شماره تماس، ادعای ۱۰۰٪ و شمارش قدیمی ویجت‌ها حذف شدند. بخش «مقالات و تصاویر شاخص» برای ترمیم مستقل بدون بازنشانی تنظیمات اضافه شد. خطاهای مقاله/تصویر به‌جای موفقیت کاذب گزارش می‌شوند.

## شواهد اجرا

`tools/qa-demo-articles.php`: **۵۸۷ assertion واقعی** روی WordPress 6.8.3، PHP 8.5.10/GD تحت WASM، DB آزمایشی SQLite و **قالب و companion فعال**. `seed_all` واقعی اجرا شد؛ سهم شش دسته، تصویر و فایل‌های اندازه میانی، metadata، عدم تکرار مقاله/attachment، حفظ نوشته مشتری با slug یکسان، حفظ thumbnail معتبر، ترمیم فایل حذف‌شده، callback مستقل OCDI بدون تغییر تنظیمات/برگه‌ها و ساختار فرم استاندارد بررسی شد.

WordPress از tag 6.8.3 و drop-in SQLite رسمی از commit `d2082798c7371934a3565d692bf7aeb6a20376da` دریافت شد؛ شبکه/ایمیل fixture مسدود بودند. Elementor، WooCommerce، افزونه OCDI و MySQL در این fixture نصب نبودند؛ **خود hook پس از import OCDI** آزموده شد، نه UI/AJAX/WXR parser افزونه OCDI. مرورگر، سایت زنده و نصب همه افزونه‌ها تأیید نشده‌اند.

سایر نتایج: ۳۰۸ assertion PHP و lint در ۸۷ فایل runtime؛ ۹۴ assertion pure؛ ۹ بررسی معماری؛ ۶ تست widget contract و ۶ تست بسته‌ساز. آزمون WebP چرخه قبل مجدداً جدا اجرا نشد؛ مسیر واقعی sideload این چرخه با ماژول روشن آزموده شد. هیچ ادعای تکمیل همه gateهای تجاری وجود ندارد.

## استفاده

قالب و companion rc.4 را هر دو نصب کنید. برای رفع نوشته‌ها در سایت دارای دمو، در بخش درون‌ریزی دمو فقط **«مقالات و تصاویر شاخص»** را انتخاب کنید؛ درون‌ریزی کامل تنظیمات دمو را بازنشانی می‌کند. پشتیبان لازم است؛ واردکننده صریحاً محتوای مقالات نشان‌دار دمو را به‌روز می‌کند، نه نوشته عادی مشتری.

آزمون توسعه فقط روی نصب محلی خالی و مصرف‌شدنی با `WP_ENVIRONMENT_TYPE=local` و `ZARINCODE_DISPOSABLE_QA=true` اجرا شود:

```sh
wp --path=/tmp/disposable-wordpress eval-file /path/to/tools/qa-demo-articles.php
```

آزمون، سایت نمونه را واقعاً می‌سازد و یک فایل تصویر را برای آزمون ترمیم حذف می‌کند؛ روی سایت عملیاتی اجرا نشود. پس از آزمون کل محیط مصرف‌شدنی حذف گردد.
