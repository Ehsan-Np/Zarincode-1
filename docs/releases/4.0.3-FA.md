# زرین‌کد 4.0.3 — پاک‌سازی کش سایت

انتشار نهایی بدون RC، ۲۰۲۶/۱۰/۳۰. قالب و هسته هر دو 4.0.3.

## استفاده
پس از پشتیبان‌گیری، هر دو بستهٔ قالب و هسته را به‌روز کنید. نیازی به ریست، درون‌ریزی یا ترمیم دوبارهٔ دمو نیست.

با حساب دارای مجوز `manage_options` یکی از مسیرهای زیر را باز کنید:
- نوار مدیریت ← **پاک‌سازی کش سایت**؛
- پنل زرین‌کد ← **پاک‌سازی کش سایت**؛
- ابزارها ← **کش سایت زرین‌کد** (در صورت غیرفعال‌شدن قالب نیز با هسته فعال قابل‌استفاده است).

دکمهٔ **پاک‌سازی کش‌های در دسترس سایت** را بزنید. بازکردن لینک، GET یا refresh صفحه نتیجه هیچ پاک‌سازی‌ای انجام نمی‌دهد. فرم POST، nonce و مجوز مدیر الزامی است. گزارش پنج دقیقه برای همان کاربر و همان سایت در دسترس است.

## چه چیزهایی پاک‌سازی می‌شوند؟
- کش آبجکت وردپرس از طریق `wp_cache_flush`؛ اگر کش ماندگار Redis/Memcached متصل باشد، نتیجه وابسته به پیاده‌سازی همان سرویس است. بدون آن، کش درون درخواست PHP پاک می‌شود؛ این جای پاک‌سازی کش صفحه نیست.
- فایل‌های CSS تولیدشدهٔ Elementor از طریق فایل‌منیجر خود آن؛ نه فایل‌های سفارشی قالب. بعداً توسط المنتور بازتولید می‌شوند.
- در نصب تک‌سایتی و در صورت موجودبودن API: WP Rocket، W3 Total Cache، LiteSpeed Cache، WP Super Cache، WP Fastest Cache، Autoptimize، SiteGround Optimizer و Cache Enabler.
- نسخهٔ CacheStorage متعلق به PWA زرین‌کد تغییر می‌کند؛ کاربر در به‌روزرسانی/فعال‌سازی بعدی Service Worker، کش آفلاین نسخهٔ تازه را می‌گیرد. بستن/پذیرفتن پیام به‌روزرسانی و قواعد مرورگر تعیین‌کننده‌اند؛ پاک‌سازی فوری از راه دور روی همه دستگاه‌ها ادعا نمی‌شود.

APIهای برخی افزونه‌ها فقط درخواست را دریافت می‌کنند؛ بنابراین نتیجهٔ «درخواست به سرویس ارسال شد» با «انجام شد» فرق دارد. خطا در یک سرویس مراحل بعدی را متوقف نمی‌کند و خطای محرمانهٔ افزونه در خروجی درج نمی‌شود.

## محدوده و ایمنی
- کش مرورگر همهٔ بازدیدکنندگان، OPcache/PHP، Nginx/Varnish میزبان و CDN مثل Cloudflare بدون اتصال معتبر خودشان قابل حذف نیستند. API افزونه ممکن است اتصال از قبل پیکربندی‌شدهٔ CDN خود را نیز اجرا کند؛ تأیید مستقل پاسخ CDN انجام نمی‌شود.
- وردپرس بدون افزونه یا سرویس کش، کش سراسری HTML صفحات ندارد. اگر سرویس در جدول دیده نمی‌شود، اتصال قابل‌استفاده‌ای شناسایی نشده است؛ نبودش را موفقیت تلقی نکنید.
- هیچ `rm`، حذف بازگشتی پوشه، پاک‌سازی کلی options/transients، نشست مشتری، سفارش، محتوای کاربر یا rewrite rules وجود ندارد. transientهای معتبر ممکن است حاوی قفل/نشست یا دادهٔ افزونه باشند و عمداً گروهی حذف نمی‌شوند.
- در چندسایتی، flush سراسری object cache و APIهای با دامنهٔ نامشخص اجرا نمی‌شوند؛ WP Super Cache با شناسهٔ سایت جاری فراخوانی می‌شود. امکان پاک‌سازی مطلق همهٔ لایه‌ها در شبکه ادعا نمی‌شود.
- قفل DB اختصاصی از اجراهای هم‌زمان جلوگیری می‌کند؛ قفل قدیمی پس از پنج دقیقه با مقایسهٔ مالک بازیابی می‌شود.

## اتصال اختصاصی هاست/CDN
توسعه‌دهنده می‌تواند listener مورداعتماد برای اکشن زیر ثبت کند؛ callback باید API معتبر میزبان را استفاده کند و فقط همان `blog_id`/دامنه را هدف بگیرد. کلیدها در تنظیمات امن همان اتصال نگهداری شوند، نه در چت یا فایل عمومی:
```php
add_action('zarincode_purge_site_cache', function (int $blog_id) {
    // Call the configured host/CDN integration scoped to this blog ID.
    // Throw on failure; do not log or expose credentials.
});
```
این اکشن خود به‌تنهایی هیچ CDN را پاک نمی‌کند؛ فقط بعد از مجوز، nonce و قفل در جریان پاک‌سازی اجرا می‌شود.

## شواهد
- `qa-cache-manager.php`: ۲۹ قرارداد مستقل با doubles؛ دسترسی، POST، nonce، mutex، خطای سرویس، خروجی امن و چندسایتی.
- `qa-cache-wordpress.php`: ۲۰ بررسی روی WordPress 6.8.3 واقعی/SQLite/PHP-WASM؛ مجوز و nonce واقعی، flush، قفل SQL، بازیابی قفل، مالکیت جدید قفل و حفظ محتوا/تنظیمات/transient معتبر.
- دو بررسی endpoint واقعی PWA نیز ثابت کردند prefix سایت ثابت می‌ماند ولی version پاسخ worker بعد از purge تغییر می‌کند؛ چرخهٔ نصب/فعال‌سازی مرورگر جداگانه تأیید نشده است.
- قرارداد عمومی: ۳۱۷ assertion و syntax-check برای ۹۲ فایل runtime؛ ۹۴ قرارداد مستقل و ۹ قاعده محدود معماری.
- افزونه‌های کش خارجی، Redis/Memcached، CDN، چندسایتی واقعی و چرخهٔ آپدیت مرورگر PWA در این نوبت نصب/اجرای انتهابه‌انتها نشدند؛ قراردادهای adapter جای آن‌ها را نمی‌گیرند. رفتار PWA با نسخه‌گذاری endpoint پیاده‌سازی شده و نیازمند آزمون مرورگر محیط مشتری است.

محیط integration یک‌بارمصرف با WordPress 6.8.3 رسمی و SQLite integration pinned به `d2082798c7371934a3565d692bf7aeb6a20376da` بود؛ ابزارها فقط با `ZARINCODE_DISPOSABLE_QA=true` و محیط `local` اجرا می‌شوند. آزمون‌ها مخرب‌اند؛ روی سایت مشتری اجرا نشوند. انتشار نهایی، مجوز تجاری یا تأیید آزمون‌های انجام‌نشده نیست.
